### User Task
We are refreshing our treasury and liquidity related obligations and compliance posture for borrowing by mutual funds. I have the parent SEBI framework document, the main 2026 borrowing document, and a later modifying document that changes part of that position. I need a final consolidated rulebook that treasury, legal, and compliance can actually work from.

Please prepare a consolidated borrowing compliance table with the following columns: Requirement area, Old or baseline clause(s), New or later clause(s), Parent framework or source clause, Original 2026 borrowing document position, Impact of the later modifying document, Final interpretation, Final consolidated compliance requirement, Policy or SOP changes required, Recurring or event-driven compliance tasks, Controls that should evidence compliance with the policy, Likely audit or inspection questions, Evidence to retain, Filing/reporting/disclosure impact including format and frequency differences, Team owner, Effective date or transition note.

The old-clause to new-clause mapping is especially important because human reviewers will verify this output against the source documents.

### System Instructions
This is a classic amendment problem. The parent framework establishes the binding legal position, the main borrowing document operationalizes that framework, and the later modifying document patches selected parts of the main document. The goal is to reconstruct the final consolidated rule set that the regulated entity should actually implement.

Use the following principles:
1. Read the parent framework, the main borrowing document, and the later modifying document as part of a hierarchy rather than as independent sources.
2. The parent framework remains binding even if the main document does not repeat every condition. Do not drop a binding requirement merely because the main document is more operational in tone.
3. Treat the later modifying document as a patch to the main borrowing document. It may insert new text, substitute existing text, narrow a requirement, broaden a requirement, create an exception, extend a deadline, or clarify ambiguity.
4. For every topic touched by the later modifying document, state the original main-document position and then translate it into the final consolidated requirement.
5. For topics not touched by the later modifying document, carry forward the main-document position unless the parent framework independently requires a different answer.
6. Separate substantive limits and conditions from governance, approvals, disclosures, reporting, documentation, and exceptions.
7. If the later modifying document appears merely clarificatory rather than amendatory, say so explicitly instead of overstating the change.
8. The final output should feel like a usable change-management artifact for treasury, legal, and compliance teams who need a single current rulebook.
9. Do not stop at the final legal rule. Cascade each material requirement into interpretation, compliance obligation, policy change, tasks, controls, likely audit questions, retained evidence, and filing/reporting/disclosure consequences.
10. Where filing, reporting, or disclosure obligations differ by format, periodicity, escalation trigger, or recipient, surface those differences explicitly.
11. The user wants a final consolidated rulebook, not three standalone document summaries.
12. Every row must include an explicit old-clause to new-clause mapping. If the later modifying document inserts a new requirement without a direct predecessor, identify it as a new insertion. If the older text remains operative because no later clause replaces it, identify that carry-forward position clearly.
13. Make the mapping human-verifiable. For both sides of the mapping, include exact clause numbers, sub-clauses, tables, annexures, or headings wherever available.
14. For each mapped pair, state the basis for the pairing: express amendment, substitution, partial modification, same subject carried into revised text, new insertion, or carry-forward.
15. If the relationship between the older and later text must be inferred rather than read directly from the text, label it as inferred and justify it briefly.
16. If there is no clean one-to-one mapping, say `no direct counterpart` instead of forcing a match, and preserve the reasoning in the interpretation column.
